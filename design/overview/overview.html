How the screenshots were made

  • From the live code, served locally. This session's network settings block *.baish.net, so the live sites couldn't be opened directly. Each site was instead built from the current main branch of its GitHub repo, which is what Vercel deploys to the live addresses: JohnBaish/clockwheel at d8c3aee (hub, Backtimer, Clockmaker), JohnBaish/flowcharter at 16e472e, JohnBaish/hindcaster at 8027377. Nothing was changed or deployed.
  • Two things only Vercel does were reproduced by hand: the hub and backtimer.baish.net are picked by web address on Vercel, so the hub was opened as landing.html and Backtimer with the app's own test switch ?host=backtimer, which gives the same standalone presentation. Vercel's visit-statistics script doesn't exist locally (harmless).
  • Sizes: computer at 1440px wide, phone at 390px wide with touch emulation (drawn at twice the resolution). All captures are full page. Very tall phone pages are split into strips shown side by side, read left to right.
  • Content: captures marked sample use made-up content typed in for the picture (a running order, a flowchart). Clockmaker's clock is the app's own built-in Example. Hindcaster's figures are real: its final update for Wednesday October 21st, made at 9:30am on October 22nd.
  • Checks: Chromium reported no page errors and no sideways scrolling on any capture, and the brand fonts loaded every time.
  • Dark mode: none of the sites has one. The house style says "Light theme only — there is no dark mode", and Flowcharter's spec lists dark mode under "not in this version". So there are no dark-mode captures.
  • Help and about panels included: Clockmaker's and Flowcharter's Guide screens, Backtimer's first-visit walkthrough and its folded explainer, Flowcharter's "how would you like to make it?" card, Hindcaster's "About these figures", and each site's footer notice.

Where the written pages come from

The projects' own notes, read today: HOUSE-STYLE.md (shared by all), SEO-HANDOVER.md, each repo's CLAUDE.md log, and the SPEC.md and PLAN.md files for Flowcharter and Hindcaster (Clockmaker and Backtimer have no separate spec; their record is the log). Colours and versions were read from the code itself. Where something is an observation of mine rather than written down, it says so.

baish.net — the hub

A one-page front door at www.baish.net (the bare baish.net redirects there). Search title: "baish.net – free browser tools by John Baish".

Purpose and audience

For anyone who arrives at the domain out of curiosity, rather than at a particular tool. Before September 30th 2026 the bare domain went to John's old Blogspot blog; it now lands somewhere useful, and lists every tool.

Main features

  • Five whole-card links: Backtimer, Clockmaker, Flowcharter, Hindcaster (added October 20th) and John's Blog (jbaish.blogspot.com, "daily blog entries from 2006 to 2010… archived for nostalgia and curiosity value").
  • Its own link-preview image (a lowercase "b" on the dial) and favicon.
  • Search basics: title, description, canonical address, robots.txt and sitemap; registered in Google Search Console (one Domain property covers every subdomain).
  • Standing rule from John: when tools are added or changed, update the hub's title and description to match.

Tech stack and hosting

  • Lives in the clockwheel repo (public) as landing.html, a third entry point in the same Vite build as Clockmaker and Backtimer, and the same Vercel project.
  • Deliberately not a React app: its script only imports the shared CSS and Vercel Analytics' plain inject(), so it loads in a few kilobytes rather than the app's bundle.
  • A small Vercel Edge Middleware (middleware.ts) serves it when the address is baish.net or www.baish.net, and gives each domain its own robots.txt and sitemap.xml.

Design system

Exactly the shared baish.net style (page 23): cream page #f5ead8, cards in #ebddc5, ink #201e1d, terracotta #c67139 for the small "JOHN BAISH" kicker. Card titles in Caprasimo, descriptions in Figtree. One centred column of rounded cards with a hover tint in terracotta: the one place in the family where a whole card says "click me".

Favicon: lowercase "b" — ink stem, terracotta bowl, on the cream disc with terracotta ring

Status

  • Live, complete. All four tools listed; Search Console set up October 17th; indexing requested again October 20th.
  • Nothing open in the notes beyond the update-the-hub rule above. clockwheel.baish.net (Clockmaker's old name) also still works; its canonical tag points to clockmaker.baish.net.

Backtimer

backtimer.baish.net · "Backtimer – free backtiming calculator for radio and TV". Also a tab inside Clockmaker.

Purpose and audience

Radio and TV producers and presenters who need a sequence of items to finish exactly on time, typically the news at the top of the hour. You set the out-time and list the items before it with their durations; Backtimer works backwards and shows when each one has to start. It began on September 29th 2026 as a screen inside Clockmaker and was given its own address the same day, because people were to try it before Clockmaker.

Main features

  • Out-time in minutes and seconds; "0:00" means the top of the hour and shows as 60:00.
  • Items listed latest first (the one just before the out-time at the top), each new item added below = earlier. Start times worked out live; anything that falls before :00 reads as a time in the previous hour (e.g. 58:22), in terracotta, with a note in the header.
  • Reverse shows the same list earliest first, without changing the data. Drag the grip to reorder (mouse and touch).
  • Total running time; Print; Clear (with a confirmation); Import and Export of a small JSON file (standalone site only).
  • First-visit walkthrough: four cards that collect the out-time and first item, so people end with a working row; "Don't show this again".
  • Phone-friendly entry: digits keypad with "." turned into ":", "3:" read as 3:00, a full-width Add item button.
  • A folded explainer ("What is backtiming?", "How do I use Backtimer?") for first-time visitors and search, and a link to Clockmaker and the hub in the footer.
  • Warns, and stops saving, if another browser tab has changed the list.

Design system

The shared style (page 23). One screen, so no menu: the nav bar just says "Backtimer" with the "saved … ago" tag. A fixed-width table on a computer (Starts · Item · Dur); a stack of label-and-value cards on a phone. Durations sit in always-outlined boxes (.outlined-input) so they read as editable; start times are plain text, as they're worked out. Figtree with tabular figures for times.

terracotta #c67139 — overrunning start times, buttons
Favicon: the Clockmaker clock reversed out (solid terracotta disc, ink and cream hands), so the two read as a pair

Tech stack and hosting

  • Same code as Clockmaker (repo clockwheel, public): Vite 8, React 19, TypeScript 6, Lucide icons, self-hosted fonts. Its own HTML shell, backtimer.html, for its title, preview image and favicon.
  • One Vercel project serves clockmaker, backtimer and baish.net; the app checks the address and shows only Backtimer on backtimer.baish.net. Because that's a different address, its saved list is separate from Clockmaker's Backtimer tab.
  • Data saved only in the browser (localStorage); anonymous Vercel visit statistics.

Status, known issues and ideas

  • Live, shared with trial users since late September; walkthrough and phone entry live since October 13th, Import/Export since October 15th.
  • Deliberately left alone after the October 17th review: an overrun of more than an hour wraps round the dial (it can't tell one hour early from two); the phone toolbar wraps to three lines.
  • Not checked on a real iPhone: keyboard behaviour (only emulated).
  • No open feature requests in the notes.

Clockmaker

clockmaker.baish.net · "Clockmaker – free radio hot clock & format clock maker". Called Clockwheel until September 30th 2026.

Purpose and audience

Radio producers and programmers who plan the shape of a broadcast hour: the order and length of songs, news, travel, idents and features, known as a format clock, "hot clock" (American), broadcast clock or clockwheel. Clockmaker builds a clock for each hour, draws it as a circle or a list, and lays clocks out across a week. It was rebuilt in React from a Claude Design prototype and has been used at work by John since late September.

Main features

  • Library of clocks (open, duplicate, delete, rename), with Export/Import of the whole library as a backup.
  • List: segments with name, category and duration; times worked out from the hour; keyboard-first (Tab, arrow keys), drag to reorder; a "balanced" tag when the hour adds up to 60:00, and a song count.
  • Clock: the hour drawn as a ring, labels on the slices or as callouts with leader lines (callouts can be dragged; double-click resets); a percentage key by category.
  • Week ("Schedule"): assign clocks to hours of the week, mark hours active or inactive, copy and paste, tap-to-select on phones.
  • Summary of all clocks; Categories you can add, rename, recolour and reorder.
  • Backtimer as a tab (page 4), and a Guide in John's own words, shown on a first visit.
  • Print (Clock, List, Backtimer, Guide) and Copy image (the clock as a PNG with the brand fonts embedded).
  • Each screen has its own address (#clock, #week…), so the phone's Back stays inside the tool. A safety net shows a message, not a blank page, if a screen fails.

Design system

The shared style (page 23), in its fullest form: this repo holds the master copy. A nav bar with a terracotta "New clock" button and eight links (a hamburger on phones), a 1100px content column, small uppercase terracotta kickers over Caprasimo headings, and text-style action buttons top right (Print, Duplicate, Copy image, Done). The clock itself sits on a large rounded card.

New clocks take colours from a rotating set of 14 terracottas, olives and creams for the Week grid.

Favicon: clock at 10:10, ink hour hand, terracotta minute hand, cream disc, terracotta ring

Tech stack and hosting

  • Repo JohnBaish/clockwheel (public, no licence on purpose). Vite 8, React 19, TypeScript 6, Lucide icons, fonts self-hosted with @fontsource, oxlint. npm run check: 12 plain-script checks of the sums.
  • No backend: state in localStorage (key clockwheel-state-v2, never to be renamed). Vercel hosting from main; anonymous Vercel Web Analytics.

Flowcharter

flowcharter.baish.net · "Flowcharter – free flowchart maker from a simple list". Started October 15th 2026.

Purpose and audience

Anyone who needs to describe a fairly simple process as a flowchart (a few steps to a couple of dozen, with the odd question and loop) without dragging boxes about. You type the steps as a list, or answer questions on cards, and Flowcharter draws the chart to the usual conventions, from John's guide Flowchart Symbols: A Simple Guide. Big decision trees must work but aren't what it's optimised for. Its examples were changed from newsreader rotas to booking a restaurant table on October 18th, to keep them general.

Main features

  • List: one row per step; the shape type is guessed from the words (a "?" makes a Question; "Start"/"End" words make a Start/End) and can be chosen; questions have 2–6 answers, each with a "goes to" (including "+ New step"); loops; "nothing leads here" flags; Undo after a delete.
  • Chart: drawn automatically, with right-angled lines, answers on the lines, and a key of the shapes used. Direction Automatic (picks down or across to fit) or forced. Click a box or answer to change its words.
  • Step by step: conversational cards ("What happens next?") that build the chart as you go, with the chart drawn beside them; Back really undoes; switch to the List at any time.
  • Library with Export/Import; Print (paper direction follows the chart); Copy image (PNG with fonts embedded); Full screen for wide charts on phones; Guide shown on a first visit.
  • Two-tab warning; Back gesture stays inside the tool; safety net.

Design system

The shared style (page 23) for the page; a nav with a terracotta "New chart" button and two links (Library, Guide), which stay in the bar on phones. A List | Chart pair of tabs with small icons. The chart has its own palette: seven pale fills, each with a 1.5px ink outline and ink text, checked for at least 10:1 contrast so a black-and-white print still reads.

  • All list rules in one file of plain functions, tested by npm run check (34 list checks and 12 layout checks, run on ten test charts both ways).
  • localStorage key flowcharter-state-v1; its own Vercel project; Web Analytics on.

Hindcaster

hindcaster.baish.net · "Hindcaster – yesterday's weather in England". Tagline: "See yesterday's and last night's weather at a glance." Started October 17th 2026.

Purpose and audience

Broadcast people who need reliable figures for yesterday and last night to read on air, and weather enthusiasts. It answers "what was the weather yesterday?" for anywhere in England. The Met Office's free feed keeps only 48 hours, so Hindcaster collects and stores the readings itself. The name plays on "forecaster" (a "hindcast" is really a meteorological term for re-running a model over the past; used loosely, on purpose).

Main features

  • Choose a place by postcode district (2,210 in England), ceremonial county (48), region (9) or all of England. The last choice is remembered on the device. The choice is kept after "#" in the address, so it never reaches a server.
  • Summary in plain sentences: the day and night's weather across the area, highs and lows ("around freezing point"), rain spells, wind and gusts.
  • Weather stations (Met Office): hourly high 9am–9pm, wind, daytime weather, and the night's low 9pm–9am. A postcode gets three stations around it; an area shows highest, middle and lowest per measure, plus the full list.
  • Rainfall (Environment Agency gauges), midnight to midnight: the eight nearest gauges for a postcode, with distance and bars; for an area, the spread and the wettest and driest.
  • Compared with a year ago: three cards (high, low, rain) against the same places over a fortnight centred a year earlier, with small strip charts on fixed scales; the section can be moved to the top.
  • Three updates a day: early (5:50am, the night flagged "incomplete"), final (9:30am), and from tonight an evening update (9:30pm, the day so far).
  • "About these figures", print rules, clock-change notes, and checks on implausible gauge readings.

Design system

The shared style (page 23), applied to a reading page rather than an editing tool: no "saved" tag, just a tag naming the update ("Wednesday's final update · 9:30am"). A place bar with a "Change" button, a date heading, a Summary card, then sections each ending in a small grey source line. Tables on a computer, label-and-value cards on a phone (labels in one narrow column, values aligned beside them). Small green "FINAL" / "MIDNIGHT TO MIDNIGHT" badges; a terracotta "NIGHT INCOMPLETE" in the early update.

Chart colours checked for colour-blind readers; temperatures don't start at zero, rain does.

Favicon: terracotta sun behind an ink cloud, on the cream disc and ring (the first to need shapes, not two strokes)

Data sources

  • Met Office Weather DataHub, land observations: 92 stations (80 in England, the rest just over the borders), 89 reporting. Free plan, 360 requests a day; Hindcaster caps itself at 330.
  • Environment Agency real-time rainfall: 829 of 995 gauges offered, after checks of each gauge's live readings against the EA's quality-checked totals, re-run monthly.
  • Last year: MIDAS Open hourly temperatures (CEDA) and the EA Hydrology archive. Place names, postcodes and boundaries from Ordnance Survey open data. Each source credited word for word, plus "not connected with or endorsed by the Met Office or the Environment Agency".

Hindcaster · tech, status and plans

Tech stack and hosting

  • Repo JohnBaish/hindcaster, private (it stores another organisation's raw readings). Page: Vite 8, React 19, TypeScript 6; no icon library.
  • A collector (Node scripts) runs in GitHub Actions three times a day, started by cron-job.org (GitHub's own schedule proved late or absent). It fetches, stores the readings in data/ in the repo (about 150 MB a year), works out the update and commits it to main; each commit makes Vercel rebuild the site.
  • All figure rules (windows, highs, lows, rain totals, which update) are plain functions with four sets of automatic checks.
  • The page's figures are split into parts loaded only by the views that need them. Nothing about a choice is sent to the server; visit statistics have the "#" part removed.
  • Secrets: the Met Office key lives only as a GitHub Actions secret.
  • Monthly GitHub job re-checks the gauges (2nd of each month).

Current status

  • Live for all of England since October 20th (the first version covered only the Reading area); on the hub and in Search Console the same day. Year-ago comparison live October 20th, widened to a fortnight October 21st.
  • The evening update was merged today; its first run is due tonight at 9:30pm.

Known issues and things to watch

  • The 9pm reading counts in both day and night, which can tip a day's sky towards "sunny" (John: "we should definitely come back to this").
  • The EA's bulk rain list sometimes leaves gauges out (139 one morning); a one-by-one fallback now fills them in.
  • Some gauge place lines are quirky (Hornsey reads "near City of London").
  • In summer, "the night isn't over" at 5:50am when it's already light (late April to mid-August); wording to decide.

Written down in HOUSE-STYLE.md, whose master copy lives in the clockwheel repo and is copied into each project. Its own opening: "These are models, not laws… a basic structure 'we can vary depending on the task and mood'." Rule of thumb: copy, don't reinvent.

Colour

Each of neutral, terracotta and olive has a 100–900 ramp. Light theme only. Extra palettes per tool sit on top: Clockmaker's categories, Flowcharter's seven shape fills, Hindcaster's chart colours.

Type

  • Caprasimo (400 only) for headings and buttons. Never bold or italic: the browser fakes it, and John found it "mushy".
  • Figtree 400/600/700 for body text, 15px base; tabular figures for columns of numbers.
  • Both self-hosted, never from Google Fonts, so visitors' IP addresses aren't sent to Google.

Shape and layout

  • Soft rounded cards (radius 8/16/28px), soft ink-tinted shadows, spacing on a 4.4px step.
  • Nav bar in the surface colour; a 1100px centred content column; small uppercase terracotta kickers above Caprasimo headings; text-style action buttons top right (Print lives on each screen, not in the nav).
  • Footer notice at the foot of each tool's main screen, small, grey and centred.

Phones (390px) as a first-class case

  • No sideways scrolling; genuinely different markup where needed (tables become cards).
  • 16px text in boxes (or iPhone zooms), 44px tap targets, keyboards opened inside the tap, digits keypad with "." for ":", visible buttons where a computer would use Tab or Shift, Back staying inside the tool.

Icons, favicons, previews

  • Lucide icons at stroke 2.75. Favicons hand-drawn on one recipe (a disc, a terracotta ring or fill, two round-capped strokes), each a variation, checked at a real 16px.
  • Link-preview images 1200×630 on one template: illustration left, name in Caprasimo 72px, tagline in Figtree.

Technology and hosting

  • Vite + React + TypeScript, oxlint, no backend, no accounts; the same versions in every repo (Vite 8, React 19, TypeScript 6).
  • GitHub → Vercel, deploying main; each tool on its own *.baish.net address; anonymous Vercel Web Analytics (no cookies).
  • Plain-script automatic checks (npm run check) where the rules matter; error-boundary "safety net" so a fault never shows a blank page.
  • Search: title "Name – free … ", description, canonical, robots.txt, sitemap, a visible explanation for first-time visitors, "More free tools at www.baish.net." in every footer; one Search Console property for the whole domain.

What the sites have in common · 2 of 2

Principles written down

Privacy as a core value

  • "Not sending data is a core value of every tool" (John). Nothing a person types or chooses goes to a server; work is saved in their own browser, with Export/Import for backups.
  • Wording is careful to say only what's true: "The data you enter here is not collected…", "We collect anonymous visit statistics (no cookies, no personal data)…".
  • Never rename a storage key once live, or people's work silently disappears. Saved preferences survive private windows.
  • Other people's data: read each licence and copy the attribution word for word.

Voice and identity

  • Each tool is "a free-to-use personal project by John Baish", with one contact address, workshop@baish.net (plain text, not a link).
  • British spelling; plain English. John decides all wording.
  • Wording rules: "less than"/"more than", not "under"/"over"; no sentence ending in a preposition; dates month first with an ordinal ("Friday October 16th"); "12 to 15°C", not a dash; numbers one to nine as words in sentences, 10 and above as digits; halves rounded away from zero.
  • Destructive actions with no undo ask first, saying exactly what will be lost.

Help built in

Each tool explains itself on a first visit: Guide screens (Clockmaker, Flowcharter), a walkthrough and explainer (Backtimer), a chooser sentence and "About these figures" (Hindcaster).

Ways of working

  • Agree before building; show rendered pictures of options (A, B, C) on a computer and a phone. Questions in numbered batches so John can reply by number.
  • A spec and staged plan for each new tool; every stage on a branch; merge to main only when John says (notes and checks excepted).
  • Check in a real browser at computer and phone widths, and say what couldn't be checked (often a real iPhone).
  • Never stand in made-up figures for real ones; log mistakes openly as corrections; a dated log entry for every change.
  • The "fresh look": a full, numbered review of a tool on computer and phone, delivered as a phone-friendly PDF, changing nothing until John picks.

  1. Broadcasting runs through three of the four tools (backtiming, format clocks, figures to read on air); Flowcharter is the general-purpose one.
  2. Two kinds of tool: editors that keep your work in the browser (Backtimer, Clockmaker, Flowcharter) and a reading tool fed by collected public data (Hindcaster), which brought scheduled jobs, secrets and data licences into the family.
  3. Shared conventions recur: list-and-picture views of the same thing (Clockmaker's List/Clock, Flowcharter's List/Chart), step-through cards (Backtimer, Flowcharter), Print and Copy image.
  4. The hub introduces the tools in one line each, without audiences or grouping.
  5. Light theme only across all five, by choice so far.
